# Peer Review Learning Loop & Branch Sync Design (v2)

**Date:** 2026-03-28
**Status:** Approved

## Problem

When the peer-review agent reviews MRs, it finds issues in code that was generated by Claude. These same mistakes recur because there's no feedback loop. Additionally, local repos may have stale remote refs when reviews start.

## Solution Overview

Two enhancements:

1. **Project-Specific Skill Generation** — After each peer review, extract CRITICAL + IMPORTANT issues into a skill file **in the reviewed project's repo** so Claude learns project-specific patterns.
2. **Branch Sync Gate** — Run `git fetch origin` + use GitLab API for MR diff to ensure reviews always use current remote state.

## Feature 1: Branch Sync Gate

### Location
`commands/peer-review.md` — new step after ticket selection, before agent spawn.

### Behavior
1. Run `git fetch origin` (safe — only updates remote tracking refs, no local changes)
2. Hard gate: if fetch fails, block review and inform user
3. Agent uses GitLab API for actual MR diff (always current from remote)
4. Local file reads use fresh remote tracking refs

### Why fetch + GitLab API
- GitLab API diff is always current (primary source of truth for MR changes)
- `git fetch` ensures any local file reads for context have fresh remote state
- No risk to working tree or current branch

## Feature 2: Project-Specific Skill Generation

### Key Difference from v1
Skills are stored **in the reviewed project's repo** (not in the shipit plugin). This means:
- Claude reads them automatically when working on that project
- No changes needed to shipit's executor agent
- Patterns are project-specific and travel with the codebase

### Skill File Location
`.claude/skills/pr-review-patterns/SKILL.md` inside the reviewed project's repo.

### Architecture

```
peer-review completes
       |
filter CRITICAL + IMPORTANT issues
       |
generalize each finding (remove MR-specific details)
       |
read existing .claude/skills/pr-review-patterns/SKILL.md (in project repo)
       |
deduplicate against ALL existing entries (cross-reviewer)
       |
append new unique patterns
       |
cap at 30 entries (CRITICAL replaces oldest IMPORTANT)
       |
write file + commit locally (user pushes when ready)
```

### Deduplication Strategy (Two-Phase)

**Phase 1: Clean up existing duplicates** — Before adding new patterns, scan the entire file for duplicates that already exist from separate review sessions by different reviewers. If two entries in the same category have >80% semantic overlap, remove the less specific one.

**Phase 2: Deduplicate new patterns** — Compare each new pattern against ALL remaining entries. If >80% semantic overlap with any existing entry, skip the new pattern.

- Match by category first (must be same category)
- Agent uses judgment for similarity (no exact string matching)
- This prevents AND cleans up duplicates even when different team members review different MRs

### Pattern Extraction Process
1. Filter review results to CRITICAL + IMPORTANT severity only
2. For each issue, extract:
   - **Category**: Security, Error Handling, Patterns, Testing, Performance
   - **Severity**: CRITICAL or IMPORTANT
   - **Pattern**: Generalized description (no file names, variable names, MR details)
   - **Prevention rule**: Concrete, actionable rule for what to do instead
3. Read existing skill file (create if missing)
4. Deduplicate across all existing entries
5. Append only genuinely new patterns
6. Enforce 30-entry cap (CRITICAL priority over IMPORTANT)
7. Write + commit locally

### Skill File Template

```markdown
---

description: Code patterns to avoid — learned from peer reviews. Read before writing code.
---
```

## Constraints

- Max 30 patterns per project skill file
- Only CRITICAL + IMPORTANT severity captured
- Patterns must be generalized (not MR-specific)
- Cross-reviewer deduplication (handles multiple reviewers)
- Git fetch only (no pull/checkout) to protect working state
- Skill file committed locally, user pushes when ready
- Best-effort: write failures don't block review completion
